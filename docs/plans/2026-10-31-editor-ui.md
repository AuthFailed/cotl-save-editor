# Editor UI Implementation Plan


**Goal:** The save editor itself: open a saves folder, see and change followers, inventory, unlocks and any raw
field by its in-game name and picture, review the changes, and export a save the game loads.

**Architecture:** A static Svelte 5 app over the codec (`src/codec`, `src/schema`). One session store holds the
opened slot and meta, the picked schema and an op list; every screen reads typed views of the tree through the
schema and writes by appending ops, so Review, undo and export see one history. Game names and pictures come from
api.cotl.info, whose ids are the save's own enum names.

**Tech Stack:** Vite 7, Svelte 5 (runes), TypeScript, `@lucide/svelte` icons, `@fontsource-variable/geist` and
`@fontsource-variable/geist-mono` (self-hosted, for offline), `vite-plugin-pwa`, Vitest, Playwright.

**Spec:** `docs/specs/2026-10-31-cotl-save-editor-design.md` (Screens, Safety, Game data). Codec: plan
`docs/plans/2026-10-31-codec.md` (done). Field names: `https://api.cotl.info/v1/save-schema.json`
(AuthFailed/cotl-api#27; until it merges, `tests/fixtures/save-schema-1.5.26.json` is served from `public/` in dev).

## Global Constraints

- Branch `editor-ui` from `codec`. Codec files change only to fix bugs, each with a test.
- Visual system (spec, variant B): ground `#0D0E10`, surfaces `#121316` / `#17181B` / `#1A1B1F`, border `#23252A`, text `#ECECEE` / muted `#A1A3AB` / faint `#7C7F88`, accent `#FF5A4E` (on-accent text `#160706`), warning `#F5B84A`; status chips Faithful `#12261A`/`#7CDB95`, Hungry `#2A2110`/`#F5C26B`, Ill `#1F1C30`/`#B9AEF5`, Dead `#2C1413`/`#FF8D84`, Elderly `#1F1E1C`/`#CFC8BE`. Geist for UI, Geist Mono for numbers and ids. Radii 6/8/10/12. A light theme from the same tokens (`prefers-color-scheme` and a toggle).
- Accessibility: real `<button>`/`<a>`/`<input>`/`<label>`; visible focus ring (2px accent, offset 2); text ≥ 4.5:1; 44 px targets below 768 px width; `prefers-reduced-motion` respected; every screen usable by keyboard alone.
- Layout B: top bar (60 px), left nav (≤ 220 px), main, right inspector (≤ 360 px). Below 768 px: nav becomes a top menu button, tables scroll in an `overflow-x: auto` box, the inspector is a bottom sheet.
- Nothing leaves the browser except GET requests to `https://api.cotl.info/v1/`. No analytics.
- Save paths (Open screen copy, verbatim):
  - Windows: `%USERPROFILE%\AppData\LocalLow\Massive Monster\Cult Of The Lamb\saves`
  - macOS (Steam): `~/Library/Application Support/Massive Monster/Cult Of The Lamb/saves`
  - macOS (App Store / Apple Arcade): `~/Library/Containers/com.devolverdigital.cultofthelamb/Data/Library/Application Support/com.devolverdigital.cultofthelamb/user/`
  - Linux / Steam Deck (Proton): `~/.local/share/Steam/steamapps/compatdata/1313140/pfx/drive_c/users/steamuser/AppData/LocalLow/Massive Monster/Cult Of The Lamb/saves`
- Field paths (1.5.26 names; always looked up by name through the schema, never by key):
  - DataManager: `CultName`, `CultFaith`, `CurrentDayIndex`, `Followers`, `Followers_Dead`, `items`, `CultTraits`, `PlayerFoundTrinkets` (tarot), `PlayerFoundRelics` (relics), `WeaponPool` (weapons), `CursePool` (curses), `DoctrineUnlockedUpgrades` (doctrines), `UnlockedUpgrades` (rituals; crown abilities too if the API's `Ability_*` ids are `UpgradeSystem.Type` names — check in Task 6, else leave crown abilities out of v1 and say so in the ledger), `UnlockedStructures` (structures), `UnlockedClothing` (outfits), `FollowerSkinsUnlocked` (forms, strings), `UnlockedFleeces` (fleeces, ints = the API fleece's `fleece`).
  - FollowerInfo: `ID`, `_name`, `SkinName`, `SkinColour`, `XPLevel`, `Age`, `LifeExpectancy`, `Adoration` (loyalty), `Traits`, `Clothing`, `Necklace`, `FollowerRole`, `_satiation`, `_starvation`, `_rest`, `_illness`, `_exhaustion`, `OldAge`.
  - InventoryItem: `type` (enum `InventoryItem.ITEM_TYPE`), `quantity`, `QuantityReserved`. Gold is `BLACK_GOLD`.
  - MetaData: `CultName`, `FollowerCount`, `Day`, `Difficulty`, `PlayTime`, `Version`.
- API mapping: an enum field's value name *is* the API id (verified 1:1 for tarot, relics, weapons+curses, doctrines, structures, items, traits, outfits, rituals via `UpgradeSystem.Type`). A follower's `SkinName` matches a skin id exactly, else with trailing digits removed (`Unicorn2` → `Unicorn`).

## Review Focus

- Unlocking or adding to a list that is `nil` in the save (never initialised) must create a list, not crash. Test in Task 3.
- Undoing one change in the middle when a later change depends on it (revive, then rename the revived follower; undo the revive) must refuse with a readable message, not apply to the wrong follower. Test in Task 3.
- A save from a game version with no exact schema: banner, edits still allowed, raw keys shown as `#key`. Test in Task 8.
- Opening the folder with several slots, then switching slots with unexported changes, must ask before discarding them. Test in Task 2.
- The API unreachable (offline, first visit): screens fall back to ids without pictures and say so; editing still works. Test in Task 4.

### Task 3: Ops, undo/redo and typed views

**Files:**
- Create: `src/model/ops.ts`, `src/model/views.ts`, `src/model/build.ts`
- Test: `tests/ops.test.ts`, `tests/views.test.ts`

**Interfaces:**
- Consumes: `MpNode`, `setValue`, `get`, `field`, `SaveSchema`.
- Produces:
  ```ts
  export type Op = { label: string } & (
    | { kind: 'set'; path: string[]; value: unknown }
    | { kind: 'insert'; path: string[]; index: number; node: MpNode }
    | { kind: 'remove'; path: string[]; index: number })
  export function apply(schema: SaveSchema, root: MpNode, op: Op): MpNode      // copy-on-write along the path; throws OpError
  export function replay(schema: SaveSchema, original: MpNode, ops: Op[]): MpNode
  export function revertOne(schema: SaveSchema, original: MpNode, ops: Op[], i: number): Op[]  // throws OpError when a later op no longer applies
  export class OpError extends Error {}
  export function nodeLike(sample: MpNode | undefined, value: unknown, type: FieldType): MpNode  // build.ts: new node in the sample's wire type, else narrowest for the field type
  export interface FollowerView { index: number; dead: boolean; id: number; name: string; skin: string; level: number; age: number; loyalty: number; traits: string[]; needs: Record<'satiation'|'starvation'|'rest'|'illness'|'exhaustion', number>; status: 'Faithful'|'Hungry'|'Ill'|'Dead'|'Elderly' }
  export function followers(schema: SaveSchema, root: MpNode): FollowerView[]
  export function inventory(schema: SaveSchema, root: MpNode): { index: number; id: string; quantity: number }[]
  export function unlocked(schema: SaveSchema, root: MpNode, fieldName: string): Set<string>   // enum names, strings, or numbers as strings
  export const ops: { rename, setFollowerNumber, revive, clone, removeFollower, setQuantity, addItem, unlock, lock, unlockAll }  // each returns Op[]
  ```
